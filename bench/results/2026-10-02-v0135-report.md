## 2. Key Technical Validations on Engine 0.1.35

1. **#467 Working Set Trimming Confirmed in Engine Log:**
   - On Coder IQ1_M startup, the engine log explicitly reported:
     `FileExpertSource: available RAM 19.16 GiB, 21.02 GiB after the mapped experts left the process working set (#467)`
   - The memory flush freed **+1.86 GiB** of available physical RAM directly from the Windows file cache, enabling the full 19.27 GiB resident cache complement to be safely locked via VirtualLock without paging errors.

2. **Coder IQ1_M Crossed 4.0 tok/s:**
   - Decode generation speed reached **4.03 tok/s** overall, with peak sustained generation at **4.20 tok/s** (40 tokens in 9.55 s).
   - VRAM Cache Hit Rate: **17.8%**.
   - MTP draft acceptance: **84.6%**.

3. **Full Q2_0 Retains Decisive Speed Lead:**
   - Sustained generation speed: **5.00 tok/s** (40 tokens in 7.97 s).
   - Draft acceptance: **97.1%**.
   - VRAM Cache Hit Rate: **12.0%**.
   - Q2_0 remains **20% to 25% faster than Coder IQ1_M** while saving **4.0 GiB of system RAM**!

4. **Zero WDDM Resets or Clamps:**
   - With `patched: true` in `BUILD.json` and our unconditional non-auto budget logic, neither model triggered Windows WDDM driver resets or VRAM cache zero-clamping.
